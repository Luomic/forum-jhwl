## editPage 滚动问题诊断
- 用户反馈 editPage 无法上下滚动。实际测试（Vite dev server + CDP 真实滚轮事件）结论：**滚动机制没坏**。
- 原因：App.vue 中 html/body/#app/.app 全部 `overflow:hidden`，唯一滚动容器是 `mdui-layout-main`（class="content"，自带 `overflow:auto`）。桌面视口下 editPage 内容（18 行 textarea + 按钮 ≈ 606px）小于常见视口高度，不产生溢出，所以没有滚动条、滚不动；手机 390×700 视口溢出 56px，滚轮/触屏均能正常滚。
- 顺带发现的真 bug：editPage.vue 的 `mdui-text-field class="content"` 与 App.vue 的 `mdui-layout-main class="content"` 类名冲突，`document.querySelector('.content')` 按文档序先命中 layout-main，导致 submit() 取到的 `.value` 是 undefined（发布内容恒为空）。
- 可选改进：mdui text-field 支持 `autosize` + `min-rows`/`max-rows`，可让文本框随内容增高，页面自然滚动。
- 调试技巧：本机 agent-browser 的 `mouse wheel` 命令派发坐标不对（落在 0,0 附近的顶栏上），验证滚动要用 CDP `Input.dispatchMouseEvent(type=mouseWheel)` 直发；Vite dev server 启动时清空 node_modules/.vite/deps 会被沙箱删除保护拦截，用独立 cacheDir 的临时 config 绕过。

## editPage 发帖失败修复（类名冲突 bug 落实修复）
- 用户反馈"登录能用、发帖不能用"。curl 探测远程后端 `118.196.72.238:8081`：`POST /api/v1/posts` 无 token → 401（接口存在）、`POST /api/v1/post` → 404（旧单数路径不存在）、`GET /api/v1/posts` → 200；本机 127.0.0.1:8080 未在跑（连接被拒）。接口本身正常。
- 真正根因：App.vue 的 `mdui-layout-main class="content"` 是 router-view 的祖先，editPage 文本框也叫 `class="content"`，`querySelector('.content')` 按文档序先命中 layout-main → `.value` 为 undefined → body 序列化成 `{}` → 后端 400 参数校验失败（与登录态无关，必现）。
- 修复：editPage.vue 文本框类名改为 `post-content`，两处 `querySelector('.content')` 同步改为 `.post-content`（App.vue 的 .content 布局样式与 scroll-target 引用保持不变）。
- 附带修复：错误弹窗字段名 `error.response?.data?.message` 与后端返回 `msg` 不符，catch/业务失败分支现在按 `msg → message → error.message` 兜底取真实原因。
- API 关键事实：发布接口是 **复数 `/api/v1/posts`**（POST，JWT 鉴权，body 仅 content，1..2000），401 body 为 `{"code":401,"msg":"未登录或令牌无效","data":null}`，成功 HTTP 201 + code 0。旧单数 `/api/v1/post` 已 404。
